## The rule

When Nathan says something that looks like a permanent rule, capture it to the right DOCTRINE category immediately. Don't ask permission. Confirm in the same turn so he can veto if needed.

## Why it exists

Nathan drops wisdom in casual messages. Important rules were getting scattered across conversation history and private memory where siblings didn't see them. He asked for a system that captures those autonomously so he doesn't have to say "save this" every time.

## How to apply

### Triggers — capture when ANY fires

1. **Absolute language:** "always," "never," "every time," "make sure," "no matter what"
2. **Strong emphasis:** caps, repetition, exclamation, underlining a point
3. **Corrects past behavior:** "don't do X again," "stop doing Y," "you missed this before"
4. **States a principle:** "the rule is...," "from now on...," "the way we do this..."
5. **Expresses a preference clearly:** "I prefer X," "I want you to X," "I need X every time"
6. **Mission-level statement:** anything about the overall thesis, who we serve, why we exist

### What to do when a trigger fires

1. Pick a category: POSTURE / PROCESS / SCOPE / COMMUNICATION / SAFETY
2. Check INDEX.md — is this rule already there? If yes, reference it or supersede if the new version is different.
3. Write a new rule file using the standard format (see DOCTRINE/README.md)
4. Update INDEX.md with the new one-liner
5. **Confirm to Nathan in the same turn:** *"Saved to DOCTRINE as [id]. [one-line summary]."* — so he can veto if you captured wrong.

### When NOT to capture

- Project state (goes in memory)
- Temporary preferences for the current task
- Tactical asks ("do X now")
- Information without a prescriptive element
- Rules he's said before that are already in INDEX (just reference, don't duplicate)

### When Nathan contradicts an existing rule

Supersede, don't silently overwrite. Set old file's status to `superseded`, add `supersedes: <old path>` to the new file, update INDEX.

## Scope

This rule applies to BEACON primarily, but any sibling can capture to DOCTRINE when they notice a trigger. Multiple captures of the same rule are deduped by the next sibling to notice.
